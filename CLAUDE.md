# Panki

A flashcard app for Japanese vocabulary, for the owner alone, on a Windows PC and an Android phone's browser, served from a small VPS. Built as if it were a large-team SaaS: clean, reused, careful, secure — the owner was burned by a messy vibe-coded project before, so **code quality and doing things properly are the point, not just "does it work."**

**This file is the one thing that survives when the owner clears their chat, so it stays a thin index — the real content lives in `docs/`.** Read the docs before touching anything. Keep them current: when the design genuinely changes, update the relevant doc in the same breath.

**Read [docs/CONVENTIONS.md](docs/CONVENTIONS.md) at the start of every task — every prompt, not once per session.** It's how code is written here and how we work together, and it's not optional: work that ignores it gets redone. Then read whichever of the docs below the task touches.

## The one rule above all others

**Never hardcode the owner's content.** Cards, decks and settings are data the owner edits through the UI; nothing of theirs is named in code — no `if (card.word === "…")`, no column named after one thing they happen to keep in it. Full rationale in `docs/CONVENTIONS.md`.

## Never open a browser — the owner's rule, 2026-10-10

**Claude never runs, drives, simulates or screenshots a browser. Not headless Chrome, not Firefox, not `pnpm verify`, not a scratch server to look at a page, not the `panki-verify` agent. No exceptions, no "just this once", unless the owner asks for it in that very message.**

- **A visual bug is fixed from what the owner says and shows** (their words, their screenshot) by reading the code. No reproducing it first.
- **A feature is built from the request and the code.** The only checks Claude runs are `pnpm typecheck` and `pnpm build`.
- **The owner is the one who looks.** The report says plainly what was changed and that it has not been seen running; they try it and say what's off.
- **If the code alone can't explain a bug, ask one short question** (which browser, what zoom, what was clicked). Never go hunting.

Why: it took far too long, cost far too much, and kept stopping to ask for permissions. The owner would rather look themselves.

## The owner's standing rules

Each is here because it kept being broken on the owner's last project. The full version is in `docs/CONVENTIONS.md`.

- **One step at a time, never ahead of what's asked.** The owner picks each step and reviews it before the next. Build the smallest thing that solves it, typecheck it, report, stop; the owner is the one who tries it. No unprompted scope, no speculative specs.
- **A new message adds to the work; it never cancels it.** When the owner sends more while Claude is working (even if it interrupts a tool call, or the harness says "stop and wait"), that is more to do, not a stop. Claude finishes what was already asked **and** does the new thing, in the same turn, without asking whether to carry on. Only the owner's own words, "stop" or "don't do X", cancel anything. (2026-10-10: Claude dropped a pop-up, a Save button and an artifact because a new request arrived mid-edit. "I didn't stop, I just sent you more stuff to work on. Unless I explicitly say to stop, continue!!!")
- **Reuse before you build.** Every shared piece is listed in `docs/COMPONENTS.md`. Extend it; never build a second thing that does the same job. Adding a shared piece means adding its line there in the same change.
- **Nothing the browser draws by itself.** No `title="…"`, no bare `<form>`, no `alert()` / `confirm()`, no classless `<button>`. The never-and-always table heads `docs/COMPONENTS.md`.
- **In-app text is product copy, never an echo of the prompt.** No narrating the mechanism, no "the user", no hint that repeats its label. **No explaining line under a setting or choice unless the owner asks for it** (2026-10-16: "we don't need this description, it's super self-explanatory").
- **It's used on a phone too.** The same app, its own layout. Nothing reachable by hover alone, nothing wider than the screen; every visible change is written for a phone's size and touch as well as a desktop (written for, not browser-tested: see above).
- **A family of mechanics is one registry.** A new kind of thing is one entry that composes with the rest, never a one-off branch, colour or badge.
- **Nothing generated goes on a card unmarked.** No text-to-speech, no LLM-written card content. The owner said it can be wrong. The one exception, their decision of 2026-10-17: a video's transcript by a speech engine (ElevenLabs Scribe, called by the API with the owner's key, like Forvo), always named as Panki's transcript where it's shown or filled from, never as the video's own words, a wrong word fixed by hand. Readings and meanings come from a dictionary database or from the owner.
- **Never start a shell command with `cd`** (2026-10-16). The working directory is already the repo root: run commands from there with paths from there (`grep -n "…" apps/web/src/app.css`, `pnpm --dir apps/api exec …`), and prefer the Read, Grep and Glob tools to `grep`, `cat` and `head`. A `cd … && …` makes Claude Code ask the owner for permission on every command, auto mode or not, and they don't want to widen permissions to stop it. A hook in `.claude/settings.json` refuses any Bash command that starts with `cd`. **Nor pipe a command's output into `Select-String`, `grep` or the like to filter it**: the check reads the filter's pattern as a file and asks too. `pnpm typecheck` and `pnpm build` are run as they are, their whole output read.

## Stack

pnpm monorepo on Node 22: `apps/web` (React 19 + Vite + TypeScript), `apps/api` (Express 5 + TypeScript, SQLite through `node:sqlite`, run with `tsx`), `apps/extension` (the browser extension, Manifest V3, built of the web's own components and styles; `pnpm build` writes `apps/extension/dist/chrome` and `dist/firefox`, loaded into the browser by hand, never deployed), `packages/contracts` (Zod schemas, the one source of truth for shapes, consumed as source so nothing has to be rebuilt). `pnpm dev` runs both; the web on http://127.0.0.1:5173 proxies `/api` to the API on 127.0.0.1:3001. Details in `docs/ARCHITECTURE.md`.
