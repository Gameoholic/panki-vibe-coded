# Word audio from Forvo (built 2026-10-15, never run against Forvo)

> **Scope of this file.** Word audio from Forvo, called by Panki's server.

> **Decided by the owner, 2026-10-15:** on Panki's server, not in the extension, and **each recording fetched is kept** as one of the account's files ("I pay for the data… we are going to do caching. This is for personal use"), though Forvo's terms say not to keep copies; keeping them is also what spares Forvo a request at every play. The key goes in Settings, or in the server's environment. It was first built in the extension the same day, then moved.

- **The server calls Forvo, nothing else does** (`apps/api/src/forvo.ts` → `createForvo(fetcher, now)`, taken by `createApp` like the clock; `routes/forvo.ts`). The key is the account's (`forvo_key`, typed in Settings), or else the server's (`env.ts` → `forvoKey`, `PANKI_FORVO_KEY`); it goes only into Forvo's own request addresses, and neither it nor a request is ever logged or sent back to a browser (`ForvoStatus` only says whose it is). `word-pronunciations` with `language/ja` and `order/rate-desc`; the answer's shape isn't documented, so each recording is read through the contracts' `ForvoItem` on its own, and one whose file isn't on an https `forvo.com` address is dropped. A word's list is remembered 90 minutes per account (Forvo's links last two hours). A recording is fetched only by its id among the word's (a browser never names an address), must come back from Forvo, is at most 2 MB and must open as an mp3 (`sniffMimes`, as any upload), and is then written as a `media` row and file with a `forvo_recordings` row, so asking for it again is the same file and no request.
- **Into the drawer** (`roles.ts` → `forvoAudio`, "Word audio (Forvo)", into a field that takes sound; `Panel` → `voiceBlock`). Once the dictionaries have answered, the word as the dictionary writes it (or as typed, when they don't know it) is asked of Panki (`messages.ts` → `askVoices`; the worker's `panki.forvoVoices`), the best rated recording kept (`askVoice`: `panki.forvoTake`, then its bytes from `GET /api/media`, to the page as base64) and heard with the app's `MediaView` from an object URL; a `Dropdown` picks someone else's when there are several; "Pronunciations by Forvo" (Forvo's own words for it) and who said it stand under it. The file's id is the card's value in that field from the start (`valuesFor`), so the card is made with it, a Required field included, and nothing follows the card. A recording kept but not added stays a file of the account. Each new word costs two of the day's 500 requests; one heard before, none.
- **In the app** (`views/SettingsView.tsx` → `WordAudioSection`, inside the Admin panel since 2026-10-17: a Source `Dropdown` over the contracts' `WORD_AUDIO_SOURCES`, Forvo alone today and disabled until a second, then the source's `KeyPanel`; `routes/wordAudio.ts`): the key typed in plain sight and saved (`api.setWordAudioKey`), then kept under a spoiler beside the line that says whose it is (none, saved, the server's), pressed to see it and pressed again to cover it (the owner, 2026-10-17; it was typed as a password and never shown again). **Since 2026-10-17 the key is everyone's** (`shared.sqlite` → `service_keys`, "The shared store" above), changed by an admin alone; each account's own key from before was moved there at the API's first start after (`gatherShared`), and the recordings stay each account's files. **Since 2026-10-18 what's fetched is everyone's too, on disk, for good** (the owner: "I want Forvo, transcriptions, YouTube thumbnails… cached globally, not per account", then "saved on disk globally, cached forever so we never go to the API for a word we already asked for in the past"). The first time a word is asked for, its list is fetched and its best liked recordings with it (`forvo.ts` → `KEPT_PER_WORD`, 8), at once, while the list's links work (they last two hours, so one fetched later would need the list again); the list as kept (`shared.sqlite` → `forvo_words`, only the recordings that came) and each recording (`forvo_recordings`: its bytes, who said it, who asked first) are kept for everyone. Every ask for that word after, by anyone, is answered from there; picking a recording copies it into the account's files, never a request to Forvo. A word's first ask costs up to nine of the day's 500 requests; a word Forvo has none of is kept as having none. There's no memory cache any more: the shared store on disk is the cache. A card still names its own account's file, so an account's cards, storage and backups stay whole on their own. The recordings accounts held before are copied in at every start that finds one missing (`gatherShared` → `gatherForvoRecordings`; the accounts' files stay).
- **Unproven:** Forvo's real answer (read from their documentation and a guess at its field names), whether its file addresses redirect off `forvo.com`, an object URL playing inside YouTube's page, Firefox. Checked on scratch copies with a stand-in Forvo: the parsing and sorting, a stranger's address dropped, Forvo's own sentence passed on, no key (`409`), a key saved and never echoed, a recording kept once and served back as an mp3, something that isn't an mp3 refused, the server's key used once the account's is forgotten.
