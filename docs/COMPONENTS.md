# Components

> **Scope of this file.** What already exists to build the app's UI with — every shared component, hook and "one home" file, and what each is for. It is imported by `CLAUDE.md`, so it is in context every session.
> **Write here:** one line per shared piece — what to reach for, and what never to hand-roll instead. Add the line in the same change that adds the piece.
> **Don't write here:** how a piece works inside (→ `ARCHITECTURE.md`), why the app looks the way it does (→ `PRODUCT.md`), or the reuse rules themselves (→ `CONVENTIONS.md`).

**Look here before building anything.** If what you need is on this page, use it — extend it if it falls short. A second thing that does the same job is exactly the mess this project exists to avoid. Everything lives in `apps/web/src/`.

## Never the browser's own

The owner's standing rule: **nothing the browser draws by itself belongs in the app.**

| Never | Always |
| --- | --- |
| `title="…"` on anything, or an SVG `<title>` (Chrome's grey hover box) | `Tip`, the app's one hint bubble (shown with a mouse; on a touch screen the words go in the menu instead) |
| a hover bubble drawn by hand | that same `Tip` |
| a bare `<form>` (Chrome's "Please fill out this field." bubble) | `Form` — `noValidate`, the fields say what's wrong in `TextField`'s own bubble |
| `alert()` / `confirm()` / `prompt()` | the question asked inside the panel that owns the action, with its cost, Cancel beside the filled `danger` button: `Ask` |
| a classless `<button>` (and its grey default fill) | `Button` (`variant="primary" \| "ghost" \| "row" \| "tab" \| "door" \| "chip" \| "seg" \| "switch" \| "item" \| "node" \| "answer" \| "danger" \| "spoiler"`, `size="md" \| "lg"`) |
| a `<select>` for a short choice | a row of `Button variant="chip"` |
| a native checkbox for something on or off | `Toggle`, a switch with its label |
| `<input type="number">` (Chrome's spinner), `type="time"` (its clock picker) | `NumberField`: a whole number typed or stepped with − and + |
| `<audio controls>` (the browser's own player), a bare `<input type="file">` (its "Choose file · No file chosen") | `MediaView`: the app's own play button, line and time; `MediaField`: the app's button and drop target, the input itself never seen. **The one exception: the Plain player style** (`MediaLook` `plain`) is `<video controls>` / `<audio controls>`, the browser's own, kept as a choice at the owner's word (2026-10-15); Panki's own Player stays the default, with its own full screen |
| a switch whose words stay the same when it flips ("On" while it's off) | `Toggle`'s `says: { on, off }`: the words say what's true now ("On" / "Off", "Required" / "Optional"); both are asked for, so neither can be forgotten |
| a centred modal over a dark backdrop (but for the one question that interrupts: `Modal`, when leaving unsaved work) | a panel anchored to what opened it *(the new-deck form opens from the header, above the list; `.panel` is the static card style; the chart's menu opens beside the box that was tapped)* |
| a colour literal (`#fff`) | a token from `theme.css` |
| a control that only shows on hover | the row's menu as well, or always shown under `@media (hover: none)` |
| "Loading…" in words, a spinner, or a part that's blank until it pops in | `Skeleton`: the shape of what's coming (the owner, 2026-10-26: "make it a skeleton whenever we do loading across the entire app") |
| the browser's own scroll bar on a box that scrolls inside itself (or `::-webkit-scrollbar` styling it) | `ScrollEdges` right after the box: a fade at the edge with more past it and a thin bar that comes up while it's scrolled or pointed at, the same in Chrome and Firefox |
